## Wire contract — verdict

From the wire/API-contract lens the fix commits (5692a4f, 6a8bfd1, 645a65c) are clean and do what their messages claim. Additive-only is re-confirmed (fix commits touch no .proto, swagger, or REST file; the full-range service.proto diff is additions only; lib message protos have zero diff). The presence-parity fix is correct — filemodel absence and present-but-empty connectivity (field 12) now match the monolith exactly, including the zero-net/zero-file-model degenerate case, proven byte-exact by a passing test I ran; the truncated-stream INTERNAL and spool fill-concurrency fixes are sound and alter no chunk ordering, which still matches the M6.1 section order exactly; the equivalence gates' deterministic-serialization comparison applied identically to both sides of a real RPC round-trip is methodologically sound, and all 10 DesignStream gates pass on a build verified current with 645a65c. Nothing P0/P1; nothing blocks merge from this lens.

### Findings
- **P2** `OdbDesignServer/Services/DesignStreamWalker.cpp:113-152` — If two layer (or step) names within one step sanitize to the same UTF-8 key (e.g. CP1252 undefined-slot bytes 0x81/0x8D/0x8F/0x90/0x9D, the exact collision class ProtobufMapHelpers.h:9-16 documents for names), the reassembled stream diverges from the monolith: features of BOTH raw layers are appended into the single surviving map entry where the monolith keeps only the last layer's records (duplication), or ApplyDesignChunk returns false when the surviving step lacks the addressed layer (reassembly failure).
  - Evidence: Monolith last-wins overwrite: StepDirectory.cpp:249-265 `(*mutable_layersbyname())[ToUtf8(key)] = *...to_protobuf()`. Walker emits a FeatureBatch for EVERY raw layer (DesignStreamWalker.cpp:113-152, no collision filter), and ApplyDesignChunk appends unconditionally into the single surviving sanitized entry (DesignStreamWalker.cpp:408-433). Same shape for colliding step names: the surviving step's skeleton matches the monolith, but the shadowed step's feature batches address the survivor and either append (duplicate) or fail lookup (applyOk=false). The service.proto DesignChunk contract comment (added in this range) claims reassembly "serializes to the exact bytes of the monolithic GetDesign response" unconditionally.   - Fix: Either track sanitized-key collisions for steps/layers in Walk and emit only the last raw key's content (matching the monolith's overwrite), or scope the contract comment's byte-exactness claim to collision-free corpora. Given ODB++ step/layer names are directory names and no fixture exhibits a collision, P2.
